How this maps to a real integration

  1. A real wearable normally syncs to the user's phone (Apple Health / Google Health Connect), or to the manufacturer's cloud (Fitbit, Garmin).
  2. Your server either runs a companion mobile app that reads from the health platform, or authorises via OAuth against the manufacturer's cloud.
  3. Whichever path you take, the result is the same: readings are POSTed to /api/sensor-data with a valid device API key.
  4. The API key you see on this page is exactly that — a real, per-device credential. The only thing this demo simplifies is the OAuth handshake, which requires public HTTPS hosting and manufacturer approval to test.
